# Documentation Standards

## Requirements

Documentation must be version controlled, reviewed with the related change and written for the intended audience.

Each technical document should identify:

- purpose and scope;
- responsibilities and dependencies;
- interfaces and data exchanged;
- failure modes and recovery behaviour;
- configuration and operational constraints;
- ownership and review triggers.

## Markdown conventions

- one level-one heading per page;
- descriptive headings and stable terminology;
- relative links for repository content;
- fenced code blocks with language identifiers;
- tables only where they improve comparison;
- diagrams represented in maintainable text formats when possible.

## Review triggers

Documentation must be reviewed after architecture changes, interface changes, incident findings, release milestones and replacement of physical or logical assets.

# ENG-000 — Engineering Registry

## Purpose

The Engineering Registry is the authoritative index of engineering practices, delivery controls and lifecycle artefacts used by Digital StarGate.

## Registered domains

| ID | Domain | Scope | Primary artefacts |
|---|---|---|---|
| ENG-001 | Development Standards | Code, scripts and configuration | conventions, reviews, documentation |
| ENG-002 | Source Control | Repository governance | branches, commits, pull requests, tags |
| ENG-003 | CI/CD | Automated validation and publication | pipelines, build jobs, deployment gates |
| ENG-004 | Testing | Verification strategy | unit, integration, contract and operational tests |
| ENG-005 | Release Management | Versioning and delivery | release notes, tags, approvals, rollback plans |
| ENG-006 | Dependency Management | External packages and tools | lock files, update policy, vulnerability review |
| ENG-007 | Quality Governance | Quality gates and evidence | checklists, reports, acceptance records |

## Registry rules

Each engineering control must have an owner, a defined trigger, measurable evidence and an escalation path. Changes to mandatory controls require an Architecture Decision Record or an approved governance update.

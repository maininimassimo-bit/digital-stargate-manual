## Closure decision

BKL-027 and BKL-028 are closed based on runtime evidence rather than design intent.

### Network

Network telemetry has already completed runtime commissioning through the N.I.N.A. Digital StarGate telemetry exporter. The observed path demonstrated current ONLINE state, gateway and Internet/DNS reachability, canonical publication, public Observatory Status rendering, and fail-safe recovery when N.I.N.A. is stopped/restarted.

Network management details that are not directly verified, including VPN and LTE failover state, remain null rather than inferred. This does not invalidate the commissioned passive network health signal.

### Power

Power telemetry is sourced from the Tecnosky TS Shelter Board J6 voltage-supervision input through `ASCOM.TS_Shelter.SafetyMonitor` and the read-only `safeties` diagnostic.

The controlled physical test established the mains-loss mask as:

```text
0x00000001
```

with observed transition:

```text
mains/J6 present  : SafetiesRaw = 0
J6 sensing absent : SafetiesRaw = 1
J6 restored       : SafetiesRaw = 0
```

The Digital StarGate adapter derives Power state from this commissioned mask, not from aggregate `IsSafe`.

Detailed evidence is recorded in:

`NINA-Power-Telemetry-Runtime-Commissioning-2026-08-27.md`

### End-to-end Observatory Status

The Observatory Status page is runtime-populated with both Network and the newly integrated Power/Alimentazione telemetry. The Power KPI and service detail are visible through the production telemetry path.

The accepted boundary remains observational/read-only. Observatory Status does not become a Safety Authority and no actuator command path is introduced.

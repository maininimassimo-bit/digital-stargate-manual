## 2. Reviewed scope

The reviewed technical head changes four files:

- the canonical Python session analyzer;
- Markdown and PDF session-report generators;
- canonical scientific-session evidence regression tests.

The hotfix resolves PHD2 fields from the GuideLog header, calculates tracking RMS from `RARawDistance` and `DECRawDistance`, applies each guide segment's pixel scale, includes `STAR_SATURATED` samples as found-but-degraded evidence, preserves rejection diagnostics, and handles both completed and failed settling.

No EAGLE uploader, N.I.N.A./PHD2 runtime configuration, observatory command path, Safety Authority, database, API, deployment topology or credential is modified.

## 3. Repository and semantic alignment

The implementation restores the semantic promise already expressed by the field names `rms_*_arcsec`: source distances in guide-camera pixels are converted to arcseconds before aggregation. Dynamic header lookup removes dependence on fixed positions, and the tests prove that reordered raw/guide-distance columns do not change the result.

The interpretation of PHD2 error code 1 is aligned with upstream PHD2 behavior: `STAR_SATURATED` remains a found star while its degraded state is retained in a separate counter. Error codes other than 0 and 1, or `DROP` rows, are excluded from RMS and retained as rejected/lost-star evidence.

Settling is fail-closed. Samples remain excluded from `Settling started` until either `Settling complete` or `Settling failed`; a new guide segment does not silently clear an active settling state.

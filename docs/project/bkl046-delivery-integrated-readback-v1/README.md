# BKL-046 · Rilettura GitHub e ricostruzione del corpus nello stesso passaggio

Il verificatore lega la rilettura della release GitHub ai byte usati per ricostruire il corpus v600. Controlla l'impronta dei due programmi esistenti e dei metadati di consegna. La rilettura verifica 81 asset, compresa la capsula di conoscenza v1.171. Il ripristino vede gli stessi 80 file del corpus mediante collegamenti NTFS sullo stesso volume. Prima della ricevuta finale il verificatore rilegge i metadati della release e controlla di nuovo gli identificativi. Il ripristino deve produrre le impronte già misurate per 10.180 oggetti e 11.839 alias.

Il collaudo locale ha accettato un caso coerente e respinto dieci varianti, tra cui una modifica della release durante il ripristino, un ID asset riusato e un rapporto di ripristino proveniente dal collaudo locale. Il collaudo usa metadati GitHub simulati e la ricevuta di una precedente ricostruzione locale. La rilettura integrata da una release effettiva resta da eseguire. La destinazione riservata e il perimetro di distribuzione sono ancora da confermare.

Il programma accetta, nell'ordine, il soggetto di consegna, l'inventario di trasporto, il piano, l'indice, i due verificatori già pubblicati, nome e ID del repository, visibilità, ID della release, tag e una nuova directory di destinazione su NTFS con spazio sufficiente. Le impronte richieste sono in `verifica-integrata.py`. Il programma effettua soltanto letture su GitHub e conserva separatamente le due ricevute originali e quella integrata.

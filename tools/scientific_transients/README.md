# BKL-051 S1 — proposed intake inspection

Offline, dependency-free preparation of a **proposed** private measurement intake contract. Not an image reader, astrometric solver, photometry pipeline, catalog client or operational portal integration. It neither establishes the truth of metadata nor manufactures consent from an actor/status field.

Run `node --test tools/scientific_transients/contract.test.mjs tools/scientific_transients/reference.test.mjs tools/scientific_transients/measurement.test.mjs tools/scientific_transients/uncertainty.test.mjs tools/scientific_transients/photometry.test.mjs tools/scientific_transients/epoch.test.mjs tools/scientific_transients/pixel.test.mjs`.

`parseIntake` rejects unknown/duplicate keys, nonfinite values, oversized/deep input, invalid dates and reused master digests as independent evidence. `inspectIntake` always returns `NO_ANALYSIS_EXECUTED` and `OWNER_CONTRACT_DECISIONS_PENDING`; even an apparently complete input receives no candidate/discovery classification. No I/O, credentials, owner paths, coordinates, scientific thresholds or external requests are present.

The limited fixture is synthetic. This tool does not change AP-013/AP-014 or ADR-019 registration/admission/quality semantics. Existing original source text, exact revisions, registry authority and byte-verification remain external prerequisites. Unknown acquisition dates and upstream History remain unknown. Input filter hashes do not establish band compatibility, and disjoint declarations do not independently prove frame independence.

See the [S1 proposal](../../docs/project/BKL-051-S1-FEASIBILITY-AND-CONTRACT-2026-10-07.md) and subsequent [ADR-020 Owner direction](../../docs/architecture/ADR-020-Private-Scientific-Transient-Analysis.md). Minimal Gaia/IRSA/MAST queries and the local PC/private portal direction were approved; this offline tool itself performs no query. Operational runtime/transport, new infrastructure and numerical scientific thresholds remain gated by their documented decisions and validation.

`reference.mjs` inspects bounded public CSV samples offline: exact string IDs, PS1 unavailable-magnitude sentinels and Gaia TCB epochs/proper-motion convention. It does not infer catalog completeness, quality, match absence or variability. Six negative/known-answer tests are synthetic and have no external I/O; the raw sample responses are retained separately in the private preparation dossier.

`measurement.mjs` inspects a proposed, closed-schema **already materialized object**, not raw JSON or transport requests. It records local-quality rejection or exploratory limitations from declarations; never grants measurement validity, band compatibility, matching, a nondetection limit, a transient classification or operating acceptance. Hash references do not independently verify bytes or truth. Nine tests cover saturation, defective apertures, crowding, negative/missing flux and unsafe declarations. A caller must separately reject duplicate JSON keys and preserve original evidence. See [reconciled evidence and residual gates](../../docs/project/BKL-051-S1-MEASUREMENT-EVIDENCE-2026-10-08.md). This module adds no I/O, dependency or operational integration.

`uncertainty.mjs` inspects a proposed materialized pair budget and performs only first-order covariance arithmetic. Unknown variances/covariances remain null; impossible complete matrices and declared read-noise double counting reject. No verified uncertainty, scientific significance, classification, threshold or consent is granted. Thirteen new tests exercise known answers and negative cases. See [the proposed uncertainty contract](../../docs/project/BKL-051-S1-UNCERTAINTY-CONTRACT-2026-10-08.md). Raw JSON duplicate-key rejection, passive data materialization and independently verified evidence remain prerequisites for a future adapter.

`photometry.mjs` adds proposed four-variable first-order calibration arithmetic with six covariance terms, explicit source color and product eligibility. Already-calibrated light curves and uncorrected aperture magnitudes are blocked; unresolved provider uncertainty semantics never produce sigma. `covariance.mjs` owns the shared normalized factorization used by this inspector and the unchanged pair contract. All inputs are passive validated declarations, not untrusted JSON/proxies or provider headers. No independence, provider statistical semantics, complete noise model, source identity or operational acceptance is inferred. See [photometric contract and retained-product diagnostics](../../docs/project/BKL-051-S1-PHOTOMETRIC-CALIBRATION-2026-10-09.md).

`tpv_coordinates.py` is an explicitly selected trusted-local diagnostic adapter using Owner-approved Astropy 8.0.1/NumPy 2.5.3 and separately pinned transitive dependencies in `requirements-astrometry-local.txt`. It reads a bounded hash-verified uncompressed primary FITS snapshot, retains original TPV distortion, and converts PI geometric coordinates by subtracting 0.5 before origin-zero WCS transformation. It neither reads remote URLs nor edits pixels, launches PixInsight, integrates queue/runtime routes, infers epoch/motion/covariance nor accepts astrometry. Missing frame remains unknown in the private NOT_VALIDATED receipt. The caller must preserve that receipt in its own exclusive journal; this function returns a materialized object and writes nothing. Run its optional mandatory CI checks explicitly with `python -m unittest tools.scientific_transients.tpv_coordinates_checks -v` after installing the separate requirements; they are not part of dependency-free cloud unittest discovery. [Contract, authorization and evidence](../../docs/project/BKL-051-S2-LOCAL-TPV-ADAPTER-2026-10-09.md).

`epoch.mjs` computes only a proposed barycentric rectilinear six-dimensional position model with explicit Julian-year TCB epochs and pmRA × cos(dec). Missing motion/distance/epoch remains incomplete. It does not propagate covariance, compute apparent place, grant matching acceptance or execute requests. Seven tests and six privately retained ESA numerical checks cover known answers, wrap and poles. See [epoch model and limits](../../docs/project/BKL-051-S1-EPOCH-MODEL-2026-10-08.md).

`queue.py` adds the Owner-approved dedicated private control namespace, tested by `python -m unittest tools.scientific_transients.test_queue`. It has no image processing or provider query; no native worker/UI/deployed OAT is claimed. Default-disabled integration and remaining gates: [S4 contract](../../docs/project/BKL-051-S4-PRIVATE-QUEUE-2026-10-08.md). Earlier offline-only descriptions apply to the individual JavaScript inspectors, not this additive candidate.

`pixel.mjs` converts explicit sample-index/native-geometric/FITS-one-based declarations offline. Unknown conventions stay incomplete; no WCS, orientation correction or science acceptance. Eleven known-answer/negative tests; [native evidence and aperture reconciliation](../../docs/project/BKL-051-S2-PIXEL-CONVENTION-2026-10-08.md). API origins require independent attestation by the future adapter.

[Contract and incomplete budget reconciliation](../../docs/project/BKL-051-S4-LOCAL-EVIDENCE-REGISTRY-2026-10-08.md). No cloud integration, credentials or scientific acceptance.

Reopened active attempts require explicit recovery, no native relaunch. `queue_receipt` has no network/lease; MemoryStore envelope tests do not attest a native/cloud worker. Run `python -m unittest tools.scientific_transients.test_queue tools.scientific_transients.test_local_registry tools.scientific_transients.test_attempt_journal`. [Contract and residuals](../../docs/project/BKL-051-S4-ATTEMPT-JOURNAL-2026-10-08.md). Shared handler denial uses bounded raw discard after half-close; auth remains unchanged.

`native_aperture.py` prepares and collects exclusive trusted-local PJSR runs; it does not launch processes or consume portal payloads. `native_aperture.jsh` calls the installed AperturePhotometry kernel, preserving normalized units and unknown variance/significance. Four native History exports plus a separate kernel receipt are retained; this is not the full photometry workflow. [Native evidence and gates](../../docs/project/BKL-051-S4-NATIVE-APERTURE-2026-10-08.md).

`native_supervisor.py` connects a fresh same-session journal/outbox to the pinned PJSR producer and an owned process handle. Explicit start/tick, no daemon, claim, credential loading or restart replay. Missing/invalid terminal or failed checkpoint save never authorizes termination; local technical completion and remote recovery remain separate. [Lifecycle and residual gates](../../docs/project/BKL-051-S4-NATIVE-SUPERVISOR-2026-10-08.md).

`local_report.py` exports private JSON/HTML from an already sealed attempt with an independently supplied exact technical report digest.
